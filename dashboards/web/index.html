Des événements bruts à un schéma en étoile testé

Ce tableau de bord est la dernière étape d'une plateforme de données construite de bout en bout pour une boutique en ligne française fictive. Les commandes arrivent de trois systèmes sources, en batch et en temps réel. Elles traversent un Delta Lake en trois couches, puis rejoignent un schéma en étoile PostgreSQL modélisé avec dbt.

Toute la plateforme tourne sur un ordinateur portable avec Docker Compose, et Airflow la reconstruit chaque nuit. Chaque chiffre de ces pages est calculé depuis cet entrepôt, avec les définitions du rapport Power BI du projet.

Comment les chiffres sont vérifiés

  • Les indicateurs reprennent les 34 mesures DAX du rapport Power BI, consignées dans dashboards/measures.dax.
  • Une seule requête SQL exporte l'entrepôt, agrégé par jour : toute période donne des totaux exacts, commandes distinctes comprises.
  • Les totaux sont rapprochés du rapport Power BI et de dashboards/check_figures.sql.
  • La page qualité lit les résultats de contrôle et l'historique des rejets produits par le pipeline lui-même.

Choix de conception

  • Chargements idempotents : un jour peut être rechargé ou une tâche relancée sans créer de doublons.
  • Les données invalides s'arrêtent avant l'entrepôt, qui garde les données de la veille.
  • Les sources se trompent exprès : doublons, événements tardifs, JSON cassé et clés manquantes, à des taux connus.
  • Un site statique sans serveur : les données tiennent dans un fichier, et la page les filtre dans le navigateur.
